02

Put it on a MiniToo

Optional · paired Windows Bluetooth device

Release the phone's display-control connection. Replace the example address with your paired device address.

POWERSHELL
.\.venv\Scripts\pixeldeck.exe configure --address AA:BB:CC:DD:EE:FF --endpoint MiniToo
.\.venv\Scripts\pixeldeck.exe run dashboard --send

--send enables display output. Add --media after input setup for supported media buttons. JPEG and 10 ms packet pacing remain the defaults.

04 / SEND

Driver

Classic RFCOMM, bounded payloads, ACKs and retries.

Static screens sleep. Identical frames are not sent again. Animations request deadlines; input arrives through callbacks.

Workers own their I/O. Rendering does not wait for Bluetooth. Audio and display still share the host, radio and device.

Closing releases the connection. The last frame remains on the MiniToo. No firmware replacement or gallery-save command is part of ordinary demos.

WHAT TO EXPECT

Small screen.
Real constraints.

Short Windows trials have demonstrated display output, media callbacks, speaker tones, microphone levels and duplex audio. Device display delay remains noticeable, even with smaller lossless frames.

Media input exposes Previous, Next and Play/Pause—not arbitrary joystick events. Exact one-action-per-press behavior, overnight endurance and phone-music coexistence remain unverified.

The gallery uses synthetic data and offline animation. It is not a promise of device frame rate.
